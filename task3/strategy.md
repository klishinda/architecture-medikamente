| Данные | В чём необходимость защиты | Инструменты защиты |
|--------|---------------------------|-------------------|
| ФИО, СНИЛС, паспорт пациента | При утечке возможна кража личности и мошенничество | Псевдонимизация в `patient_uuid` хранение; отдельное зашифрованное хранилище; TLS при передаче |
| Диагнозы, история болезни, назначения врача | Врачебная тайна, раскрытие грозит уголовной ответственностью | AES-256 для файлов, ABAC (только лечащие врачи) |
| Результаты лабораторных анализов | Специальная категория ПДн (ВИЧ, онко и т.д.), обмен с внешней организацией | AES256 в S3, использование псевдонимизации при передаче в лабораторию (`order_id`); TLS |
| Медицинские файлы, снимки, документы | Содержат снимки и подписи, врачебная тайна | S3 с AES256, разграничение доступов |
| Телефон, email пациента | Контактные ПДн, риск фишинга и спама при утечке | маскирование, доступ по ролям |
| Паспортные данные пациента | Высокий риск мошенничества | маскирование серии и номера, доступ по ролям |
| Платёжные данные | Финансовые ПДн | 1С в клиент-серверном режиме, без файлов; TLS между ККМ и 1С; RBAC - только кассир и бухгалтер |
| Зарплата, кадровые данные сотрудников | Разглашение трудовой информации, нарушение ТК | шифрование, RBAC (HR, руководители) |
| Трудовые договоры, СНИЛС/ИНН сотрудников | Данные с персональными и корпоративными данными | S3 AES256, RBAC (HR, руководители), логирование |
| Данные для НДФЛ | Содержат ФИО + доходы сотрудников, передаются вовне | TLS при передаче, разделение доступа |
| Резервные копии баз данных | Бэкапы сейчас хранятся долго и без защиты | отдельный бакет в S3 |
| Конфигурации, пароли, секреты | Риск компрометации паролей, доступность | Vault и запрет хранения в git и env-файлах, проверка на уровне SonarQube |
| JWT-токены, пользовательские сессии | Компрометация токена, перехват доступа к данным пациента | HTTPS only, политика обновления refresh token |

---

Все данные уровня ПДн шифруются по алгоритму AES-256 в состоянии покоя (at rest) и передаются исключительно по TLS 1.3 в состоянии передачи (in transit). Ключи шифрования хранятся в выделенном KMS (Vault) и ротируются каждые N дней. Межсервисное взаимодействие защищается взаимной аутентификацией (mTLS). Доступ к данным ограничивается по принципу минимальных привилегий: RBAC на уровне API Gateway и Row Level Security на уровне СУБД. Все операции с персональными данными и документами фиксируются в централизованном логировании.
